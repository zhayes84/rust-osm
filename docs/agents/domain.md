# Domain Docs

Before exploring, read the root `GLOSSARY.md` and relevant ADRs in `docs/adr/`. If these files do not exist, proceed silently.

Use the glossary's vocabulary for domain concepts in issue titles, proposals, refactors, and tests. If a needed concept is missing, note it for `/domain-modeling`.

If work conflicts with an ADR, call out the conflict explicitly rather than silently overriding it.

This repo uses a single-context layout: one root `GLOSSARY.md` and `docs/adr/`.
